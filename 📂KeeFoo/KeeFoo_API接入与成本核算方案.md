## 一、 API 接入路线图 (Roadmap)

针对项目 Day 01-04 暴露的 AKShare 稳定性问题及多智能体联邦架构的需求，建议分三阶段推进：

### 阶段 1：金融数据源“专业化” (1-2周)
*   **目标**：解决腾讯云环境下的行情断流，提升 Weaver (编织者) 的素材质量。
*   **动作**：
    *   **主干**：从原生 AKShare 升级至 **Tushare Pro (积分商业版)** 或 **Ricequant (米筐) 基础版**，确保 WebSocket 实时性。
    *   **冗余**：保留 AKShare 作为本地代理层 (Proxy)，仅用于低频宏观数据抓取。
*   **负责人**：CTO (接口封装) + 产品经理 (权限采购)。

### 2. 阶段 2：多模型“联邦化” (2-4周)
*   **目标**：在“逻辑深度”与“成本”间取得平衡。
*   **模型矩阵策略**：
    *   **Sentinel (哨兵/提取)**：使用 **DeepSeek-V3** (性价比极高，处理长文本提取)。
    *   **Weaver (编织者/关系)**：使用 **Claude 3.5 Haiku / GPT-4o-mini** (逻辑连接稳定性好)。
    *   **Judge (法官/审计)**：核心灵魂，使用 **DeepSeek-R1** 或 **GPT-4o** (具备强推理能力，执行苏格拉底式质询)。
*   **架构需求**：由 CTO 搭建统一的 **LLM Proxy Gateway**，实现模型热切换与自动降级。

### 3. 阶段 3：影子仓位“数据流闭环” (1个月+)
*   **目标**：实现影子仓位的极端情境自动推演。
*   **动作**：引入新闻舆情 API (如：财联社/新华社实时快讯接口)，通过 Sentinel 自动匹配用户影子标的。

## 三、 成本管理方案 (Cost Management Scheme)

为了防止“杨总的钱包被智能体烧光”，制定以下“铁律”：

1.  **语义缓存策略 (Semantic Cache)**：
    *   **Redis 拦截层**：针对重复的市场宏观事件（如：美联储加息），Weaver 生成的关系图谱缓存 6 小时。
    *   **审计去重**：如果用户多次输入相似的交易理由，Judge 直接调用缓存的审计逻辑，减少重复推理。
2.  **按需激活 (On-Demand Activation)**：
    *   L3 Judge 仅在用户完成“三轨数据采集”后才启动，不在信息流刷新时白嫖 Token。
3.  **Token 熔断机制**：
    *   设置单次审计 Token 上限（如 15,000 tokens），超过则由 Sentinel 自动截断非关键信息，保护 API 额度。
4.  **模型梯队自动降级**：
    *   非关键时段或非核心用户，自动将 Judge 模型从 R1 降级为 V3 基础版，成本可瞬间压缩 70%。
