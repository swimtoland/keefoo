## 一、产品定位与核心价值重述

在你描述的基础上，我建议将产品定位收窄为：

> **「AI 驱动的个人金融资产信息助理」**——不做投资决策，做信息决策。

这个定位有两层含义：

- 对监管：我是信息工具，不是投顾服务

这个区隔非常重要，贯穿整个产品逻辑。

## 二、完整产品逻辑架构

```
用户层

  └── 实时预警（重大事件触发）
  └── 定时日报（每日收盘后）
  └── 周报 / 月报（持仓回顾）
```

## 三、核心难点：走势预测的法律风险规避

这是整个产品最敏感的部分，需要在**产品设计、文案表达、法律结构**三个层面同时处理。

### 3.1 监管红线认知

根据中国现行法规，**提供证券投资建议**需持有中国证监会颁发的**投资顾问牌照**（个人）或**基金投资顾问资质**（机构）。无牌照做「预测」「建议买卖」属违规。

关键判断标准是：你的内容是否构成「具体的投资建议」。

### 3.2 三层规避策略

**第一层：产品定性为「信息汇编工具」而非「投顾服务」**

在用户协议、产品介绍、小程序类目申请中，明确写明：

> 本产品提供的所有内容均为公开信息的汇编与分析，不构成任何投资建议，不对用户的投资决策及结果承担法律责任。投资有风险，入市需谨慎。

**第二层：语言表达的系统性替换**

|禁止表达|替换表达|
|---|---|
|「预计该股下周上涨」|「近期多项技术指标呈现偏多信号」|
|「建议买入」|「市场情绪偏积极，关注度上升」|
|「该基金未来收益较好」|「同类基金近期表现参考区间为 X%-Y%」|
|「风险较低」|「历史波动率处于近一年低位」|

核心原则：**描述信号，不给结论；呈现数据，不做判断**。

**第三层：走势模块的产品形态设计**

不做「预测」，做「情景推演」：

```
【多空信号面板】
  技术面信号：MA/MACD/RSI 综合评分 ——「偏多 / 中性 / 偏空」
  资金面信号：北向资金、大单流入方向
  情绪面信号：舆情热度、机构持仓变化
  宏观面信号：利率环境、行业政策风向

【情景参考】（替代「预测」）
  情景A（乐观假设）：若 XX 政策落地 / XX 数据好于预期，历史上类似情境下该类资产表现为……
  情景B（中性假设）：维持当前基本面，参考近 3 个月均值区间……
  情景C（压力假设）：若 XX 风险事件发酵，历史类似情境下最大回撤参考……
```

这个设计的本质是：**用历史情景类比替代直接预测**，用户自行判断对应哪个情景，产品不给最终结论。

## 四、数据与技术架构建议

### 4.1 数据源优先级

|数据类型|推荐数据源|
|---|---|
|A股行情|同花顺 iFinD、Wind 万得（商业授权）；免费可用 AKShare、Tushare Pro|
|基金数据|天天基金网抓取（需注意协议）、聚合数据基金 API|
|债券/期货|Wind、同花顺；期货可用期货交易所官方数据|
|贵金属|上海黄金交易所官方接口、Bloomberg（成本高）|
|财经资讯|东方财富、新浪财经 RSS、同花顺资讯 API|
|监管公告|证监会官网、上交所/深交所公告接口（均有官方数据服务）|

**早期建议优先使用 Tushare Pro + AKShare 组合**，成本可控，覆盖主流品种。

### 4.2 Agent 设计要点

推荐采用**事件驱动 + 定时轮询**双模式：

- **事件驱动**：监管公告、重大价格异动（涨跌停、净值偏离）触发实时推送
- **定时轮询**：每日收盘后跑全量分析，生成日报

Agent 的个性化相关性判断是核心竞争力：同一条新闻，持有该股的用户和未持有的用户，推送的权重和解读深度应该完全不同。

### 4.3 推送频控设计

用户极容易因信息过载而取消订阅，这是此类产品最大的流失原因。建议：

- 实时预警：每日上限 3 条，仅触发真正重大事件
- 日报：每日收盘后 1 条，固定时间（如 17:30）
- 允许用户自定义：哪些品种需要实时提醒，哪些只看日报

纯订阅制是最干净的模式，与你的主营方向一致，同时也最有助于规避「利益冲突」的法律质疑（即不能因为推荐某标的而获得佣金）。

```
免费层：关注 3 个标的，每日基础日报
基础会员（X元/月）：关注 20 个标的，实时预警，完整日报
专业会员（XX元/月）：无限标的，情景推演模块，周期深度报告，优先客服
```

**明确不做**的事项同样重要：不接受标的方的商业合作推广，不做付费排名，这是产品公信力的底线。

## 六、MVP 开发路径建议

建议分三个阶段：

**Phase 1（1-2个月）：跑通核心链路** 手动导入标的 → Tushare 拉取行情 + 公告 → GPT/Claude 生成日报文本 → 公众号模板消息推送。先不做小程序，先验证内容质量和用户留存。

## 二、交易策略归纳引擎

这是复盘系统的 AI 核心，难度也最高。

### 2.1 策略特征提取维度

```
时间维度
  ├── 持仓周期分布（超短线 / 短线 / 中线 / 长线 各占比）
  ├── 交易频率热力图（哪些月份、星期几、时间段交易最活跃）
  └── 市场环境偏好（牛市 / 震荡 / 熊市 中各自的胜率）

标的维度
  ├── 偏好行业/板块分布
  ├── 偏好市值区间（大盘蓝筹 / 中小盘 / 微盘）
  ├── 偏好估值区间（低PE价值型 / 高PE成长型）
  └── 集中度习惯（是否喜欢重仓单一标的）

行为维度
  ├── 买入信号来源（技术突破型 / 消息驱动型 / 逢跌买入型）
  ├── 止损执行率（设了止损是否真的止损）
  ├── 止盈习惯（是否倾向于过早止盈 / 拿不住盈利单）
  └── 追涨杀跌指数（买入时标的近5日涨幅均值）

认知偏差诊断
  ├── 处置效应（过早卖出盈利仓位、持有亏损仓位过久的程度）
  ├── 过度交易倾向（换手率 vs 同期指数收益对比）
  ├── 集中风险偏好（是否总在特定行业过度集中）
  └── 情绪化交易识别（大跌后次日是否有非计划性操作）
```

### 2.2 策略画像输出样式

```
【你的交易策略画像】

核心风格：消息驱动型中线投资者
置信度：较高（基于 127 笔历史交易）

优势特征：
  · 在政策利好消息发布后 48h 内买入的交易，平均盈利率 +8.3%
  · 持仓 15-45 天的交易胜率最高，达 64%
  · 对新能源、半导体板块的判断显著好于其他板块

需注意的模式：
  · 存在明显处置效应：盈利单平均持仓 18 天，亏损单平均持仓 41 天
  · 周五下午 14:30 后的买入操作，胜率仅 38%（可能受情绪影响）
  · 过去 3 次重仓（仓位>30%）操作中，2 次出现较大回撤
```

## 三、原子信息图谱系统

这是产品最有差异化价值的部分，也是 Obsidian 知识库的核心内容结构。

### 3.1 原子节点类型定义

金融知识图谱的原子单元分为六类：

```
Asset（标的）     ── 股票、基金、债券、期货合约、贵金属品种
Entity（实体）    ── 上市公司、基金公司、基金经理、监管机构、券商
Event（事件）     ── 财报发布、政策出台、高管变动、评级调整
Trade（交易）     ── 用户每一笔买入/卖出记录
Macro（宏观）     ── 利率决议、CPI数据、汇率波动、大宗商品周期
Note（笔记）      ── 用户自己记录的交易理由、情绪、复盘思考
```

````markdown
## 四、AI 复盘报告生成逻辑

### 周报生成流程
```
Step 1：收集本周所有 Trade 节点 + 关联 Event 节点
Step 2：计算本周盈亏贡献归因（哪笔交易贡献了多少）
Step 3：对照用户历史策略画像，判断本周操作是否符合自己的优势区间
Step 4：提取本周出现的认知偏差信号
Step 5：生成 Markdown 周报，自动插入 Obsidian
```

### 报告语气设计原则

复盘报告的 AI prompt 需要特别设计，避免两个极端：
- **不做裁判**：不说「你这笔操作是错的」，只说「这笔操作与你过去同类情景下的决策存在差异」
- **不做马后炮**：不用结果倒推过程对错，要基于买入时的信息环境来评价决策质量

## 五、技术实现路径

### 5.1 Obsidian 同步方案

用户本地 Obsidian + 云端生成结合：
```
云端（你的服务器）
  └── AI 分析引擎生成 .md 文件
  └── 推送到用户的 Git 仓库 或 WebDAV 服务

用户本地 Obsidian
  └── 通过 Obsidian Git 插件 / Remotely Save 插件自动同步
  └── 用户可直接编辑、批注、添加个人笔记
```

这个架构的好处是：**AI 负责生成结构化内容，用户保留完整的本地数据主权**，不存在数据在你服务器上的隐私顾虑。

### 5.2 核心技术栈建议
```
数据层：    Tushare Pro / AKShare（行情） + 用户手动/OCR导入（交易记录）
存储层：    PostgreSQL（结构化交易数据） + Neo4j（图谱关系）
AI 层：     Claude API（复盘报告生成、策略归纳） 
文件层：    Python 生成 Markdown + Git/WebDAV 同步至用户 Obsidian
小程序层：  图谱可视化（ECharts 力导向图）+ 交易录入界面
````

### 5.3 图谱可视化（小程序内）

Obsidian 的 Graph View 在小程序内无法直接用，需要自己实现：

- 使用 **ECharts 的 graph 力导向图**，节点颜色区分六类原子类型
- 点击节点展开详情，边的粗细代表关联强度（共同出现次数）
- 支持按时间范围过滤，查看「某段持仓期间的完整信息宇宙」

## 这个商业模型的本质

传统 SaaS 是**先付费再用功能**，你的模型是：

## 收费节点的精确设计

不能等用户自己意识到要付费，需要主动设计触发时刻：

```
第 30 天
  └── 推送：「你已完成 12 笔交易，初步策略轮廓正在形成」
  └── 给一份残缺版报告，核心结论模糊处理
  └── 目的：让用户看到价值的轮廓，产生好奇

第 60 天  
  └── 推送：「我们发现你在周五下午的交易胜率显著偏低」
  └── 具体数据不展示，付费后解锁
  └── 目的：用具体的认知偏差发现制造焦虑感

第 90 天
  └── 完整复盘报告生成，封面可见，内容加锁
  └── 推送：「你的第一份完整投资复盘已生成」
  └── 同时展示：报告页数、覆盖交易笔数、发现的策略特征数
  └── 目的：用「完整感」触发付费冲动
```

第 90 天的推送是最关键的转化节点，文案要非常克制——**不渲染功能，只陈述事实**：「你有 127 笔交易记录、3 个已识别的决策模式、1 份完整复盘在等你」。

## 定价策略

你说不会太低，这个判断是对的。原因有两个：

第一，你的目标用户不是散户小白，是**有真实资金在跑、有复盘意识的投资者**。这类用户对工具付费的心理价位远高于普通 App。

## 断点三：90 天真空期的留存问题

话术上需要比真实持仓的推送更加保守：

```
真实持仓推送：
"降准事件对你持有的 XX 债基产生直接影响，
历史同类情境下该类基金平均反应为 +1.2%~+2.8%"

"你关注的 XX 债基今日遭遇降准事件，
历史同类情境下该板块走势可供参考"
```

模拟仓永远不出具体数字区间，只给方向性参考。一旦出具体数字，就很容易被认定为投资建议。

## 为什么是服务号而不是订阅号

你的产品有三个关键需求，订阅号全部满足不了：

**第一，微信支付。** 你的付费订阅体系必须走微信支付，订阅号没有微信支付权限，服务号有。

**第二，小程序关联。** 服务号可以与小程序深度打通，用户从公众号菜单直接跳转小程序，体验无缝。订阅号的跳转路径更长，摩擦更大。

**第三，模板消息推送。** 你的核心功能是「及时推送」，服务号每月可发 4 次主动推送，更重要的是可以通过模板消息做事件触发型通知（价格异动、报告生成等）。订阅号的推送会被折叠进「订阅号消息」里，用户基本不看。

---

## 但注册之前要想清楚一件事

服务号需要企业主体认证，个人主体注册不了服务号——只能注册订阅号。

所以你现在面对的实际问题是：

```
个人主体  →  只能注册订阅号  →  缺失支付和深度推送能力
企业主体  →  可以注册服务号  →  功能完整，但需要营业执照
```

---

## 我的建议

**现在不要急着注册任何公众号。**

原因很直接：你现在连 MVP 都还没有，公众号注册了也没有内容可以推送，放在那里只会因为长期不更新被用户取消关注，冷启动的时候反而是负资产。

真正应该做的事，按优先级排：

**第一件事：注册一个公司主体。**

不需要大动作，个人独资或者有限公司都可以，主要目的是拿到营业执照，为后续服务号认证、小程序上线、微信支付申请做准备。这三件事都需要企业主体，早注册早省事。

**第二件事：等 MVP 有了基础形态再注册服务号。**

理想的节奏是：MVP 能跑通核心链路的时候，同步完成服务号注册和认证，这样注册完立刻就能用，不会浪费空窗期。

**第三件事：服务号的第一批内容要想好。**

服务号每月只能主动推送 4 次，每一次推送都很珍贵。第一批内容不是产品介绍，而是对目标用户有实际价值的复盘方法论内容，用内容建立信任，再引导关注小程序。

---

现在最值得花时间的一件事，是把 MVP 的核心链路跑通——OCR 导入、个性化日报生成、影子仓位推送。这三个功能验证完，公司注册、服务号注册、小程序上线可以同步推进，节奏会很流畅。
