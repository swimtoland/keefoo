# KeeFoo 产品设计总览
> 整合自 Claude + Gemini 两轮深度对话，提取核心决策，去除重复推演，作为开发前产品设计基准文档。
> 整理日期：2026-03-29

---

## 一、产品定位

> **「AI 驱动的个人投资第二大脑」**
> 记录你做了什么 → 理解你为什么这样做 → 归纳你的决策模式 → 在下次决策前调出相关记忆

- **不做投资决策，做信息决策**；不预测未来，只复盘过去
- **合规定性**：信息汇编工具 / 个人投资记录与历史分析工具，**非投顾服务**
- 核心关键词：「及时」「高度定制」「人工智能」
- 竞争对手不是同花顺、东方财富，而是**用户自己的 Excel 记账表**

---

## 二、产品形态（三端分工）

```
微信公众号（服务号）  ── 内容推送、拉新入口
微信小程序（输入侧）  ── 交易快速录入、持仓概览、原子信息流、实时预警
Web 端（输出侧）      ── 知识图谱、复盘报告、策略画像、完整笔记系统
```

**小程序 vs Web 分工逻辑**：
- 小程序：数据持续输入 + Agent 实时处理 + 轻量展示，用户从第一天就有价值
- Web 端：数据积累 3~6 个月后，提供深度复盘、图谱生成、策略归纳

> 小程序不做 Graph View，用**「原子卡片 + 关联跳转」**实现轻量双链

**为什么不做 App（当前阶段）**：
- 冷启动获客成本乘以 3–5 倍；iOS 金融类 App 审核有资质门槛
- 小程序做验证 → Web 验证付费 → 12 个月后再做 App

## 三、合规策略（三层）

**第一层：产品定性**
- 用户协议、产品介绍、小程序类目均明确：「本产品提供的所有内容均为公开信息的汇编与分析，不构成任何投资建议」

**第二层：语言表达系统性替换**

| 禁止表达 | 替换表达 |
|---|---|
| 「预计该股下周上涨」 | 「近期多项技术指标呈现偏多信号」 |
| 「建议买入」 | 「市场情绪偏积极，关注度上升」 |
| 「该基金未来收益较好」 | 「同类基金近期表现参考区间为 X%-Y%」 |
| 「风险较低」 | 「历史波动率处于近一年低位」 |

> 核心原则：**描述信号，不给结论；呈现数据，不做判断**

**第三层：走势模块形态**
- 不做「预测」，做「A/B/C 情景推演」（乐观 / 中性 / 压力假设）
- 用历史情景类比替代直接预测，用户自行判断对应哪个情景
- **模拟仓推送永远不出具体数字区间**，只给方向性参考

## 四、核心数据模型

> 所有数据围绕一个中心问题：**「用户在什么时间、什么市场环境下、基于什么信息、做了什么决策、结果如何」**

### 核心实体（7 张表）

| 实体 | 核心字段要点 |
|---|---|
| **User** | user_id、wechat_openid、risk_profile、base_currency |
| **Asset**（标的） | symbol、asset_type、sector、tags、linked_entities |
| **Trade**（交易）⭐ | direction、price、position_ratio、market_context（买入时自动快照）、trigger_event_ids、decision_note、emotion_score、paired_trade_id、pnl_rate、exit_reason |
| **Position**（持仓快照） | avg_cost、market_value、unrealized_pnl、weight_in_portfolio（每日收盘自动生成） |
| **Event**（事件库） | event_type、sentiment、impact_level、related_assets、asset_reaction_1d/5d（事后回填） |
| **Entity**（机构/人物） | entity_type、linked_assets、latest_events |
| **MarketMacro**（宏观） | indicator、value、deviation_from_expect |
| **ReviewReport**（复盘报告） | period_type、strategy_tags_detected、bias_detected、report_content_md、graph_snapshot |

### 图谱关系（Neo4j）

```
(Trade)-[TRIGGERED_BY]->(Event)       ← 最核心连线，边有丰富属性
(Trade)-[INVOLVES]->(Asset)
(Trade)-[MADE_BY]->(User)
(Asset)-[BELONGS_TO]->(Sector)
(Asset)-[ISSUED_BY]->(Entity)
(Event)-[AFFECTS]->(Asset)
(Event)-[INVOLVES]->(Entity)
(Entity)-[MANAGES]->(Asset)
(MarketMacro)-[CORRELATES]->(Asset)
(ReviewReport)-[COVERS]->(Trade)
```

**`TRIGGERED_BY` 边的属性（核心竞争壁垒）**：
- `information_latency`：事件发生到交易执行的时滞（判断是"先手"还是"接盘"）
- `market_temperature`：交易时的恐慌贪婪指数
- `agent_inferred_bias`：AI 推断的认知偏差（FOMO、Panic_Selling、处置效应等）
- `user_confirmation`：是 Agent 推断的还是用户确认的

### 图谱双层架构

```
公共图谱（系统预建，所有用户共享）
  └── 标的 ↔ 行业 ↔ 宏观指标基础关系网络
  └── 历史事件对标的影响的统计关系
  └── A股所有上市公司股东/管理层/关联方

用户私有图谱（随使用逐步生长叠加）
  └── 用户的 Trade 节点
  └── 用户关注过的 Event 节点
  └── decision_note 中提及的逻辑链
```

> 新用户 Day 1 走公共图谱，私有图谱随时间叠加，解决图谱冷启动问题

## 五、Agent 编排架构

采用**状态机（State Graph）**而非线性 Chain，三个触发入口：

```
触发节点
  ├── 分支 A：事件驱动 → 价格异动 >5% 或重大公告（实时）
  ├── 分支 B：定时轮询 → 每日收盘后，生成日报与持仓快照
  └── 分支 C：用户动作 → 交易录入或 OCR 账单导入
       ↓
上下文召回（查询用户 Position 快照，打包 Context 对象）
       ↓
L1 线性计分粗筛（规则引擎，零 Token 消耗）
  · 直接涉及持仓标的   +50
  · 涉及关联实体       +25
  · 同板块联动         +15
  · 纯宏观背景         +5
  · 用户历史行为权重   +10
  Score < 15 → 直接丢弃
       ↓
L2 图谱游走精筛（Neo4j 路径匹配）
  验证 (Event)-[AFFECTS]->(Asset) 与用户 Position 能否形成逻辑闭环
  无法闭环 → 剪枝丢弃
       ↓
L3 逻辑审判庭（Critic Agent，调用 Claude API）
  · 默认拒绝（Default Deny）原则
  · 强制寻找"该信息无价值"的三个理由
  · 同时进行多空博弈对抗验证
  · 置信度 < 90 分 → 归档，不推送
  通过 → 输出 Pass + 推演理由
       ↓
分发与落库
  高优先级 → 推送原子信息卡片到小程序
  低优先级 → 写入事件库，晚间日报聚合
  用户确认交易逻辑 → 写入 Neo4j TRIGGERED_BY 边
```

**成本控制规则**：
- 只有 impact_level = high 的事件才进入 L3
- 每用户每日 L3 调用上限：10 次
- 超出上限降级为日报聚合，不做实时验证

**单次算力成本估算**（100 条原始资讯，单支基金）：

| 阶段 | 模型 | Token 消耗 | 费用（DeepSeek 计价） |
|---|---|---|---|
| 持仓穿透 API | 传统代码 | 0 | ¥ 0 |
| 粗筛去重 | 轻量模型 | ~32,000 | ¥ 0.032~0.064 |
| 对抗验证 | 强推理模型 | ~18,000 | ¥ 0.018~0.036 |
| 报告生成 | 强推理模型 | ~2,500 | ¥ 0.002~0.005 |
| **合计** | | **~52,500** | **¥ 0.05~0.10 / 次** |

> 单客月度算力成本 < ¥10，订阅模式毛利健康

## 六、decision_note 获取机制（三轨并行）

> 表单填写 >50% 极度反人性，必须用以下三轨替代

**轨道一：延迟追问（苏格拉底式访谈）**
- 触发时机：交易导入后 2~4 小时（情绪落定但记忆未消退）
- Agent 自动拉取当日环境信息，反向提问：「你今天在 20.5 建仓了某科技股，今天板块有政策利好，你是基于中线逻辑还是短线突破？」
- 每笔交易最多追问一次，问题不超过 40 字
- 前端呈现为极简单选卡片

**轨道二：意图解析（隐式结构化）**
```
用户输入："主要是赌下周财报"
↓ Agent 解析
decision_type:  event_driven
time_horizon:   short
confidence:     medium（"赌"字暗示不确定性）
emotion_score:  6
structured_note: "财报预期驱动，短线博弈"
```

**轨道三：沉默推断**
- 用户持续沉默本身是数据，反向推断情绪状态，估算 emotion_score
- 有效 decision_note 覆盖率目标：**>70%**
  - 用户主动填写 30% + Agent 对话解析 40% + 沉默推断兜底 30%

## 七、小程序信息架构

> 设计哲学：**信息不再按时间流排列，而是按「与用户持仓的关联强度」聚合**

### 原子信息卡片（四层关联）

```
第一层：标的直连 → 财报、公告、重大价格异动
第二层：实体关联 → 基金经理换人、大股东减持、券商评级调整
第三层：板块/生态关联 → 同板块龙头异动产生联动
第四层：宏观传导链 → 推送"降准对你持仓的传导路径"，而非单纯推送"降准了"
```

**卡片样式**：
```
┌─────────────────────────────────────┐
│ 🔴 高关联  财报事件                  │
│ 贵州茅台 Q3营收同比+15.2%            │
│                                     │
│ 与你的关联：                         │
│ · 你持有 100股，成本价 1650          │
│ · 上次因财报买入，持仓18天盈利7.3%   │
│                                     │
│ 关联信息 ──────────────────────     │
│ [📊 动销数据存疑] [👤 管理层表态]    │
│ [🏦 机构净买入] [📈 板块联动]        │
└─────────────────────────────────────┘
```

### 噪点过滤流程

```
信息入库 → 关联度评分（L1规则） → 图谱游走（L2） → 逻辑验证（L3）
→ 去重合并（同一事件多源 → 合并一张卡片）
→ 推送给用户
```

**推送频控**：
- 实时预警：每日上限 3 条，仅触发真正重大事件（价格异动 >5%、重大公告）
- 日报：每日收盘后 1 条，固定时间（如 17:30）
- 板块联动信息：日报聚合；宏观背景信息：周报聚合

### 小程序三个核心页面

```
首页「我的信息流」  ── 按关联强度排序的原子卡片流（非时间流）
标的详情页         ── 该标的所有关联信息聚合 + 我的持仓记录 + 历史事件时间轴
持仓概览页         ── 极简仓位结构 + 每个标的今日关联信息数量角标
```

### 影子仓位（观望仓）

- 用户可导入「错过」或「正在观望」的标的作为模拟仓
- 当系统抓到重大事件时，对模拟仓推送情景推演（**不出具体数字，只给方向**）
- 作用：将价值显现从 Day 90 提前到 Day 3~15，大幅提升冷启动留存

## 八、Web 端复盘系统

### 交易策略归纳引擎

分析维度：
- **时间维度**：持仓周期分布、交易频率热力图、不同市场环境胜率
- **标的维度**：偏好行业、市值区间、估值区间、集中度习惯
- **行为维度**：买入信号来源、止损执行率、追涨杀跌指数
- **认知偏差诊断**：处置效应、过度交易、情绪化交易识别

### 策略画像样式
```
【你的交易策略画像】
核心风格：消息驱动型中线投资者（基于 127 笔历史交易）

优势特征：
  · 政策利好 48h 内买入的交易，平均盈利率 +8.3%
  · 持仓 15-45 天的交易胜率最高，达 64%

需注意的模式：
  · 存在明显处置效应：盈利单平均持仓 18 天，亏损单平均持仓 41 天
  · 周五下午 14:30 后买入，胜率仅 38%
```

> **报告语气设计原则**：不做裁判（只说"与过去同类情景存在差异"），不做马后炮（基于买入时的信息环境评价决策质量）

## 九、用户生命周期与价值时间轴

```
Day 1   绑定持仓 → 立即生成「今日关联信息摘要」（当天即有价值）
Day 3   添加观望仓 → 首次收到情景推演推送（第一个「啊哦」时刻）
Day 7   第一笔交易录入 → Agent 首次苏格拉底追问
Day 15  「你已积累足够数据，初步行为特征正在生成」
Day 30  第一份残缺版报告，核心结论模糊处理（引发好奇）
Day 60  「我们发现你在周五下午的交易胜率显著偏低」（付费焦虑触发）
Day 90  完整复盘报告生成 → 核心付费转化节点
```

> 免费期不是亏损，是在替用户**建立迁移成本**。三个月后用户面对的不是「要不要续费」，而是「我三个月的记录全在这里，我舍得走吗」

## 十、商业模式

**订阅制（纯净模式，无利益冲突）**：

| 层级 | 价格 | 内容 |
|---|---|---|
| 免费 | ¥0 | 关注 3 个标的，基础日报 |
| 基础复盘版 | ¥99~199/月 | 20个标的、季度复盘、策略画像、原子图谱 |
| 专业版 | ¥299~499/月 | 无限标的、月度+周度复盘、偏差追踪、完整图谱、数据导出 |

- 年付享约 7 折，锁定长期用户
- **明确不做**：不接受标的方商业合作推广，不做付费排名
- **数据政策**：免费期结束后数据保留 X 天，到期清除（须在免费期内反复告知）

## 十二、MVP 三阶段路径

**Phase 1（1~2 个月）：跑通核心链路**
- OCR 账单导入 / 手动录入标的
- Tushare 拉取行情 + 公告
- GPT/Claude 生成个性化日报文本
- 公众号模板消息推送
- **验证指标**：个性化日报是否让用户愿意留下来

**Phase 2（3~4 个月）：小程序 + 个性化**
- 上线小程序，实现持仓可视化
- 原子卡片 + 关联跳转
- 苏格拉底追问系统上线
- 公共图谱预建，图谱游走精筛投入使用
- 影子仓位 / 观望仓功能
- 情景推演模块

**Phase 3（5~6 个月）：Web 复盘 + 商业化**
- Web 端知识图谱、复盘报告、策略画像上线
- 引入更多数据源（研报、北向资金）
- 上线会员体系
- 完善频控和用户偏好设置

## 十三、冷启动策略

**核心认知**：有复盘习惯的投资者是最挑剔的一批人，免疫「AI 赋能投资」话术。不能广撒网，要用极高诚意打动极少数的对的人。

**三条路径**：

1. **代理人内容策略**（成本最低）
   - 找有真实交易经历、有复盘习惯、愿意公开表达的「投资者合伙人」
   - 在雪球以真实数据持续输出复盘方法论内容，工具自然带出

2. **私域种子用户**（质量最高）
   - 目标：50~100 个种子用户（雪球粉丝 1000~5 万的腰部投资博主）
   - 逐一私信，内容极度个性化，不发群发消息
   - 给永久专业版，要求写一篇真实使用体验发在雪球（不强制好评，强制真实）

3. **渠道合作**（杠杆最大）
   - 财经播客合作（用产品换内容，非广告）
   - 不要做抖音、公众号矩阵，目标用户不在那里

**关键建议**：现在不融资、不找机构，先把种子用户的「啊哦时刻」设计出来
